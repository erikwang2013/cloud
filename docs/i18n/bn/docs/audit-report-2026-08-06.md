## ৩. ক্রিটিক্যাল সিকিউরিটি সমস্যা (P0 / P1)

### P0-1. Apple `id_token` ভেরিফাই করা হয়নি —— সরাসরি অ্যাকাউন্ট টেকওভার
**ফাইল**: `service/app/user/service/OAuthService.php:180-192` (`appleProfile()`)

```php
$parts  = explode('.', $tokenData['id_token']);
$claims = json_decode(base64_decode($parts[1]), true);   // শুধু base64 ডিকোড, সিগনেচার/iss/aud/exp ভ্যালিডেশন নেই
```

আক্রমণকারী নিজেই `id_token` তৈরি করে যেকোনো ইমেইল দিয়ে OAuth লগইন জাল করতে পারে। `resolveUser()` ইমেইল দিয়ে বিদ্যমান ইউজার ম্যাচ করে সরাসরি টোকেন ইস্যু করে → **যেকোনো অ্যাকাউন্ট টেকওভার**।

**ফিক্স**: Apple JWKS (`https://appleid.apple.com/auth/keys`) + `Firebase\JWT\JWT::decode($idToken, $keys, ['ES256'])` দিয়ে সিগনেচার ভেরিফাই, এবং `iss=appleid.apple.com`, `aud=client_id`, `exp`, `nonce` ভ্যালিডেট।

### P1-1. OAuth লগইনে `email_verified` ভ্যালিডেট করা হয়নি
**ফাইল**: `OAuthService.php:163-178, 282-303`

Google/Facebook/Microsoft/LinkedIn সবাই `email_verified` ফিল্ড রিটার্ন করে, কোড সম্পূর্ণ উপেক্ষা করে। প্রোভাইডারে ইমেইল ভেরিফাইড না থাকা ইউজার সেই ইমেইল দিয়ে সরাসরি নিবন্ধিত অ্যাকাউন্ট বাইন্ড/টেকওভার করতে পারে। GitHub পাথ `verified` ভ্যালিডেট করে (সঠিক), বাকি প্রোভাইডারগুলোতে ইউনিফর্ম ভ্যালিডেশন প্রয়োজন।

### P1-2. রেট লিমিট মিডলওয়্যার আছে কিন্তু কখনো মাউন্ট হয়নি —— ডকুমেন্ট ও বাস্তবায়ন অসামঞ্জস্যপূর্ণ
**ফাইল**: `common/Security/RateLimitMiddleware.php` + `config/security.php` + `config/route.php`

- `security.php`-এ login=5/min, register=3/min ইত্যাদি রেট লিমিট রুল কনফিগার করা আছে
- `RateLimitMiddleware` **কোনো রাউটে রেফারেন্স করা হয়নি** (পুরো রিপোজিটরি grep করলে শুধু ক্লাস নিজেই)
- `docs/features.md` দাবি করে লগইন "রেট লিমিট 5 req/min", রেজিস্ট্রেশন "রেট লিমিট 3 req/min" —— বাস্তবে নেই
- ঐতিহাসিক অডিট রিপোর্ট (`security-audit-2026-08-04.md`) এই আইটেমটি OK চিহ্নিত করেছিল, শুধু কনফিগ দেখে মাউন্ট ভেরিফাই করেনি, এই রাউন্ডে সংশোধন করা হয়েছে

**প্রভাব**: লগইন/রেজিস্ট্রেশন/ফরগট পাসওয়ার্ড/রিসেট পাসওয়ার্ড/রিকভারি কোড/ক্যাপচা ইত্যাদি পাবলিক এন্ডপয়েন্ট সীমাহীন ব্রুটফোর্সযোগ্য (লগইন শুধু per-account লক, ক্রেডেনশিয়াল স্টাফিং ও IP লেভেল স্প্যাম প্রতিরোধ করে না)।

**ফিক্স**: `RateLimitMiddleware` `/api/auth/*`, `/api/captcha/*` ইত্যাদি পাবলিক রাউটে মাউন্ট করুন (গ্লোবাল `''` গ্রুপে লাগানো যাবে, `route` প্যারামিটার দিয়ে আলাদা করা যাবে)।

### P1-3. TOTP 2FA লগইন ফ্লোতে বাধ্যতামূলক নয়
**ফাইল**: `AuthService.php:64-97` (`login()`) + `AuthController.php` + `config/features.php`

`user->totp_enabled` শুধু `totpVerify/totpDisable/totpRecoveryCodes`-এ চেক হয়, **`login()` কখনো ভ্যালিডেট করে না**। 2FA চালু থাকা ইউজার এখনও শুধু পাসওয়ার্ড দিয়েই বৈধ access token পায় —— 2FA অকার্যকর (`FEATURE_TOTP` ডিফল্ট চালু)।

**ফিক্স**: লগইনে `totp_enabled` থাকলে টেম্পোরারি টোকেন ইস্যু করুন এবং TOTP ভেরিফিকেশন পাসের পর আনুষ্ঠানিক টোকেন দিন (অথবা totp code প্যারামিটার দাবি করুন)।

### P1-4. নোটিফিকেশন চ্যানেল প্লেসহোল্ডার বাস্তবায়ন —— ইমেইল ভেরিফিকেশন/পাসওয়ার্ড রিসেট প্রোডাকশনে অকার্যকর
**ফাইল**: `app/Notification/Queue/EmailSender.php`, `SmsSender.php`, `PushSender.php`

তিনটি কনজিউমারই শুধু `error_log()` দিয়ে পাঠানো সিমুলেট করে এবং `send_status`-কে `sent` লেখে। ফলাফল:
- **ফরগট পাসওয়ার্ড ফ্লো ভাঙা**: `AuthController::forgotPassword()` ভেরিফিকেশন কোড তৈরি করে "পাঠায়", কিন্তু মেইল কখনো পৌঁছায় না → ইউজার নিজে পাসওয়ার্ড রিসেট করতে পারে না
- রেজিস্ট্রেশন ইমেইল ভেরিফিকেশন, নতুন IP লগইন অ্যালার্টও একইভাবে অকার্যকর
- `.env.example`-এর `SMTP_*`/`MAIL_FROM_*` মোট ৭টি ভেরিয়েবল কোনো কোড পড়ে না (ডেড কনফিগ)

**ফিক্স**: রিয়েল মেইল পাঠানো সংযুক্ত করুন (PHPMailer/SendGrid SDK), বিভ্রান্তিকর `sent` স্ট্যাটাস মার্ক অপসারণ; অথবা স্পষ্টভাবে অসম্পূর্ণ ফিচার হিসেবে চিহ্নিত করে ডকুমেন্ট থেকে সংশ্লিষ্ট প্রতিশ্রুতি অপসারণ করুন।

## ৬. অপ্টিমাইজেশন সুপারিশ (নন-ব্লকিং)

1. **সার্ভিস DI-করণ**: `AuthController` কনস্ট্রাক্টরে সরাসরি `new AuthService()/OAuthService()` — কন্টেইনারে সংযোগের সুপারিশ (webman নেটিভলি সাপোর্ট করে), টেস্ট ও প্রতিস্থাপন সহজ হবে।
2. **আপলোড ডিরেক্টরি হার্ডেনিং**: ডিরেক্টরির ভিতরে `index.html` রাখুন, PHP এক্সিকিউশন নিষিদ্ধ করুন (nginx `location ~ \.php { deny all; }`)।
3. **WAF রেজেক্স কনভার্জেন্স**: `security.php`-এর `sqli_patterns`-এ `\b(select|update|delete|...)\b` ইত্যাদি বিস্তৃত প্যাটার্ন আছে, গ্লোবাল রেট লিমিটে ইউজার টিকেট/রিভিউতে এই শব্দগুলো এলে 403 ভুলবশত ব্লক হতে পারে; শুধু সেনসিটিভ প্যারামিটারে কার্যকর করা বা রেজেক্স শক্ত করা উচিত।
4. **লগ অডিট**: `AuditLogger::record('user_registered', ['user_id' => null])` নতুন ইউজার ID রেকর্ড করে না, আসল ID নিবন্ধনের সুপারিশ।
5. **OAuth টেস্ট কভারেজ**: `OAuthServiceTest` URL কনস্ট্রাকশন ও code এক্সচেঞ্জ কভার করে, কিন্তু `resolveUser()` (DB পাথ) ও Apple সিগনেচার ভেরিফিকেশন পাথের টেস্ট নেই; P0 ফিক্সের পর অবশ্যই সিগনেচার ভেরিফিকেশন ব্যর্থতার টেস্ট কেস যোগ করতে হবে।
6. **CI সংযোগ**: প্রজেক্টে `.github` ডিরেক্টরি আছে, GitHub Actions যোগ করার সুপারিশ: `composer install && phpunit` + `composer audit`, রিগ্রেশন প্রতিরোধ।
7. **HTTP মেথড কনস্ট্রেইন্ট**: OAuth রাউটে GET/POST callback দুটোই রেজিস্টার করা যুক্তিসঙ্গত (Apple-এর প্রয়োজন), বাকি পাবলিক রাইট অপারেশন এক্সপ্লিসিট POST, OK।
