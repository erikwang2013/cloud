## 発見した業務コード問題（未修正、制約に従い記録のみ）

1. **Alert.context の二重エンコード**：`AlertEngine::trigger()` が `json_encode($context)` の文字列を `Alert::create` に渡すが、Alert モデルの `context` は `array` cast のため setAttribute で再度 json_encode → 落庫は二重エンコードとなり、読み戻した `$alert->context` は配列でなく JSON **文字列**になる（`app/Monitor/Service/AlertEngine.php` + `app/Monitor/Model/Alert.php:20`）。テストは実挙動でアサートしコメント済み。提案：AlertEngine は配列を渡す。
2. **Domain register のドメイン二重点**：`DomainService::register()` が `$domainName . '.' . $tld` で連結するが、tld 設定テーブルはドット付き `.com` を保存 → `example..com` になる（`app/Domain/Service/DomainService.php:40`）。テストは実挙動でアサートしコメント済み。提案：tld のドットを除去してから連結する。

## 残存ギャップと原因

| ギャップ | 原因 |
|------|------|
| ResourceMonitor の collectAllMetrics / checkDowntime / checkSslCertificates | Redis + ProviderFactory（実プロバイダー呼び出し）と TLS ソケットプローブに依存。mock 層か統合環境が必要で、単体テストのコストが高い |
| ProductService の ES メインパス（searchKeywordIds が ES にヒット） | 実 ES コンテナが必要（既存の ProductSearchTest は markTestSkipped で手順を注記済み）。単体テスト環境のコンテナに scout engine がなく、`Product::search` は空配列を返して例外を出さないため、SQL 降格ブランチは単体テストで発火不可 |
| NotificationDispatcher のテンプレート描画（getLocalizedTitle/body） | 既存の NotificationDispatcherTest が基本パスをカバー済み。テンプレート多言語描画は I18n 層の責務 |
| Graphql resolver の実行（products クエリの実返却） | resolver は Product/Resource/Order モデルに依存。Schema 構造はカバー済み、実行パスは API 統合テストで実施推奨 |
