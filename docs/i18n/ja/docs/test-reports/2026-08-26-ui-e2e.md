## 問題と失敗分析

### 問題 1（擬似エラー、欠陥ではない）：直リンク時に `Cannot read properties of undefined (reading 'Account')`
- 現象：スキャン時に `/app/admin/xxx/index` へ直リンクすると、permission.js が `window.Admin.Account` undefined を報告。
- 原因：`window.Admin` はメインフレームの index.html でのみ注入されるため、直リンクの子ページ（メインフレームなし）では欠落。
- 結論：実際の利用パス（サイドバークリックで iframe に入る）ではこのエラーは発生せず、欠陥ではない。

### 問題 2（実質的な小欠陥）：アバター空時に `<img src="null">` が 404 を発火
- 現象：user 一覧ページ読み込み時に `/app/admin/user/null` をリクエスト → 404 コンソールエラー。
- 根本原因：`admin/app/view/user/index.html:273`（admin/index.html も同様）：
  `'<img src="'+encodeURI(d['avatar'])+'" ...'` — avatar 行が NULL の場合 `encodeURI(null)` → 文字列 `"null"` になり、ブラウザが相対パスとして `/app/admin/user/null` に解決。
- 影響：アバターが空の行が壊れた画像 + 404 コンソールログ 1 件のみ。機能影響なし。
- 提案：`encodeURI(d['avatar'] ?? '')` にするか、空値なら img を描画しない。

### 問題 3（環境差異、欠陥ではない）：36 のモデルが `erik_*` テーブルを指すが DB に存在しない
- 現象：本 DB の実テーブルは `orders/products/...` だが、`admin/app/model/` の 36 モデルの `$table = 'erik_xxx'` のため、これらの一覧ページのテーブルにデータがない（ページ自体は 200 で正常描画）。
- 説明：一時 `CREATE TABLE erik_* LIKE 基表` + e2e_ テスト行の挿入でこれらのページのデータ描画チェーンが利用可能なことを検証し、検証後にすべて削除済み（現在 `erik_%` テーブルは 0 枚）。これは命名不一致の環境問題であり、後続での統一を推奨。

```bash
# 1. テストインスタンスを起動/確認（コードは repo と同期、8788 で待機）
# 2. メインスクリプトを実行（ログイン→51 ページスキャン→iframe ナビゲーション→詳細モーダル→ログアウト）
node /tmp/ui-e2e2/run-e2e.js
# 3. メニューナビゲーション + 詳細モーダル特化（frame スクリーンショット問題は修正済み）
node /tmp/ui-e2e2/final-nav-test.js
```

要点：
- ログインにはレート制限あり：ログイン API は 5 回/分、全ページスキャンは 60 回/分（RateLimitMiddleware、Redis スライディングウィンドウ）。スクリプト内蔵で 429 時は 61 秒待ってリトライ（最大 4 回）。2 回の実行間隔は ≥ 65 秒を推奨。
- CAPTCHA は `runtime/sessions/session_<PHPSID>` から読み取るため、php CLI の実行が必要。
- 結果は `/tmp/ui-e2e2/results.json` に出力、スクリーンショットは `docs/test-reports/screenshots/2026-08-26-e2e/` に出力。
- 一覧データの描画を検証する場合：先に `admin/app/model/` の `erik_*` テーブル名でコピーを作成しテスト行を挿入（`/tmp/ui-e2e2/create-erik-copies.sql.sh` + `seed.sh`）、実行後は `drop-erik-copies.sql.sh` + `rollback-seed.sh` でクリーンアップ。
