## 残存ギャップ / 発見した問題

1. **`pick_ip` の octet 越界ラップアラウンド**（`orchestrator.rs` の `ip_to_u32`）：`10.0.0.300` が受け入れられ `10.0.0.44` に切り詰められる。PHP の `ip2long` は >255 で false を返す。現在のテストはこの挙動を記録済み（`pick_ip_invalid_input_returns_none` の末尾にコメント付きアサート）。修正には業務コードの変更が必要で本タスクの範囲外。Phase 2 で `ip_to_u32` に `p <= 255` の検証を推奨。
2. **統合テストは外部サービスに依存**：`tests/integration.rs` はローカル MySQL+Redis がある場合のみ実実行（環境変数なしではスキップ）。今回の CI 式検証は mock パスのみ実行。
3. **`HttpClient::health` / 実 HTTP 往復**（ecat-client）は未カバー：実 HTTP サーバーが必要。既存の test 依存がなく、後続に持ち越し。
4. **gRPC 実接続**（kvm-server）：`check_auth` とメッセージエンコード/デコードは単体テスト済み。tonic チャネル接続は未テスト（実サーバー起動が必要）。
5. workspace の残り約 60 の ecat-* crate は本タスクの範囲外（タスク指定は kvm-server + ecat-lock + ecat-client）。後続要求があれば続けて展開可能。

## 暴露して修正した実バグ

**`HealthRegistry::with_check` が tokio ランタイム内で `blocking_write()` を呼ぶと panic**（`Cannot block the current thread from within a runtime`）。
- トリガー：ルートレベルテストが `#[tokio::test]` 内で `with_check` をチェーン呼び出し（従来は同期テストのみで未発見）。
- 修正：`pub async fn with_check` + `self.checks.write().await` に変更（最小変更、`ecat-health/src/lib.rs:28`）。
- 影響面：本番コードに呼び出し元なし（grep では crate 内テストのみ）。API セマンティクスが同期から async に変わるが安全な修正。
