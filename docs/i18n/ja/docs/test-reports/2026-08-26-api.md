- `POST /api/auth/register(暗号化)` [auth-flow] status=-1 期待=0 備考: code=-1 msg= エンベロープ内=Server internal error —— User モデルの Encryptable cast に 16 バイトキー(aes-128-ecb)が不足、ユーザー作成で即 500（アプリケーション欠陥）

## 制限事項
- Stripe 決済は外部サービス: `POST /api/orders/{id}/pay` はエラーハンドリングパス（4xx/5xx）のみ検証、実際の決済は完了不可
- service の `/admin/api/*` エンドポイント: 一般ユーザートークンは 401/403（AdminRole/RBAC）になるはず。管理者トークンには service 側の管理者アカウントが必要（本環境では未設定）
- admin のマスターキー問題（B1）は修正・再テスト済み: 8788 が正常起動、captcha/dashboard/dict/export/login/CRUD の全ルート利用可（コピーは完全なルートファイルに更新済み）
- admin パネル（8788 コピー）: 全ルート利用可、ログイン連鎖（captcha+session+bcrypt）が token を正常に返却。観察事項: user/order/product/config 一覧 API がセッション cookie なしでアクセス可能（HTTP 200、未認証）
- 登録（service の両パスとも 500）: User モデルの Encryptable cast に 16 バイトキー不足（aes-128-ecb、MissingEncryptionKeyException）→ 登録不可・ユーザートークン取得不可のため、トークン付き認証ケースは全体スキップ。ログインは CAPTCHA 単回有効 + ログイン可能なユーザーが存在しないため、401/422 のエラーパスのみ検証可能
- 公開エンドポイント: 今ラウンドで products/{id}、help/{slug}、stripe webhook、domain/* はすべて正常復帰（以前の ModelNotFoundException 500 と domain_tlds の列欠落問題は修正済み）

- WAF（security-php プラグイン）: dns_rebinding 検出器が Host=127.0.0.1 を内部アドレスと誤判定してブロック（アプリケーション設定問題、W1-W3 の範疇）。本スイートは `TEST_HOST` 環境変数でドメイン Host（本番デプロイ形態）を送信して回避。IP 自動ブラックリスト（max_attempts=5）はファイル保存で、テストトラフィック発火後 15 分で自動解除
