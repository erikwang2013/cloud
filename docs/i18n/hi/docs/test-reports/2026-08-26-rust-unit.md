## अवशिष्ट अंतराल / पाई गई समस्याएँ

1. **`pick_ip` octet सीमा पार रैप** (`orchestrator.rs` की `ip_to_u32`)：`10.0.0.300` स्वीकार होकर `10.0.0.44` में कटता है, जबकि PHP `ip2long` >255 पर false लौटाता है। वर्तमान टेस्ट यह व्यवहार रिकॉर्ड करता है (`pick_ip_invalid_input_returns_none` के अंत में टिप्पणीबद्ध एसर्शन); फिक्स के लिए व्यावसायिक कोड बदलना होगा, इस कार्य के स्कोप से बाहर, Phase 2 में `ip_to_u32` में `p <= 255` जांच का सुझाव।
2. **इंटीग्रेशन टेस्ट बाहरी सेवाओं पर निर्भर**：`tests/integration.rs` को वास्तव में चलने के लिए लोकल MySQL+Redis चाहिए (पर्यावरण चर न होने पर स्किप), इस बार की CI-शैली सत्यापन केवल mock पाथ चला।
3. **`HttpClient::health` / वास्तविक HTTP राउंडट्रिप** (ecat-client) कवर नहीं：वास्तविक HTTP server चाहिए, कोई मौजूदा test डिपेंडेंसी नहीं, बाद के लिए छोड़ा।
4. **gRPC वास्तविक कनेक्टिविटी** (kvm-server)：`check_auth` और मैसेज कोडेक यूनिट टेस्टेड हैं, tonic चैनल कनेक्शन टेस्टेड नहीं (वास्तविक सर्वर साइड चाहिए)।
5. workspace के बाकी ~60 ecat-* crate इस कार्य के स्कोप में नहीं हैं (कार्य ने kvm-server + ecat-lock + ecat-client निर्धारित किया), बाद में चाहें तो जारी रखा जा सकता है।

## सामने आया और फिक्स किया गया वास्तविक बग

**`HealthRegistry::with_check` tokio रनटाइम के भीतर `blocking_write()` कॉल करने पर panic करता है** (`Cannot block the current thread from within a runtime`)।
- ट्रिगर：रूट-स्तर टेस्ट `#[tokio::test]` में चेन के रूप में `with_check` कॉल करता है (पहले केवल सिंक्रोनस टेस्ट कॉल करते थे, सामने नहीं आया)।
- फिक्स：`pub async fn with_check` + `self.checks.write().await` में बदला (न्यूनतम बदलाव, `ecat-health/src/lib.rs:28`)।
- प्रभाव क्षेत्र：प्रोडक्शन कोड में कोई कॉलर नहीं (grep से केवल crate के भीतर टेस्ट उपयोग करते हैं), API सेमेंटिक्स sync से async हुआ, सुरक्षित फिक्स है।
