## टेस्ट केस विवरण

### 1. लॉगिन (वास्तविक कैप्चा) — PASS
प्रवाह：GET `/app/admin/account/captcha/login` → `runtime/sessions/session_<PHPSID>` से डिसेरियलाइज़ कर `captcha-login` वाक्यांश पढ़ें → POST `/app/admin/account/login`।
परिणाम：`{"code":0,"nickname":"Administrator","msg":"登录成功"}`।
विवरण：कैप्चा वाक्यांश सर्वर सेशन फ़ाइल में सादा संग्रहीत है, कैप्चा छवि का OCR नहीं किया गया——सीधे सेशन पढ़ना "मानव द्वारा चित्र देखकर कोड डालने" के समतुल्य है।

### 2. मुख्य फ्रेम और साइडबार — PASS
`/app/admin/index/index` HTTP 200; साइडबार 8 समूह रेंडर करता है (डेटाबेस/अनुमति प्रबंधन/सदस्य प्रबंधन/व्यवसाय प्रबंधन/सामान्य सेटिंग्स/प्लगइन प्रबंधन/डेवलपमेंट सहायक/उदाहरण पेज) + डैशबोर्ड; `window.Admin` index.html द्वारा इंजेक्ट किया जाता है।

### 3. पेज स्कैन 50/51 — PASS (1 डिज़ाइन के अनुसार 404)
प्रत्येक पेज पर एसर्शन：HTTP 200, पेज शीर्षक, टेबल कंटेनर, कोई JS त्रुटि नहीं। `dev/index` 404 डिज़ाइन के अनुसार है (डेवलपमेंट सहायक मेनू प्लेसहोल्डर, दोष नहीं)।

### 4. मेनू क्लिक → iframe नेविगेशन — PASS
साइडबार `[menu-url]` क्लिक पर user/order/supplier/ticket चार मेनू आइटम, सभी संबंधित iframe खोलते हैं (URL मेनू आइटम से मेल खाता है), iframe में टेबल सामान्य रूप से रेंडर होती है। स्क्रीनशॉट：frame-user-index.png।

### 5. विवरण/संपादन पॉपअप — PASS
user पेज पर "संपादित करें" क्लिक → layui layer (type=2) iframe `/app/admin/user/update?id=M7P9GEMYk8JEk` खोलता है, शीर्षक "संशोधन", पॉपअप में फ़ॉर्म रेंडर होता है। स्क्रीनशॉट：frame-user-detail.png। डिलीट/बैच ऑपरेशन केवल पॉपअप पुष्टिकरण बॉक्स तक सत्यापित किए गए, वास्तव में सबमिट नहीं किया गया (केवल-पठनीय बाधा)।

### 6. लॉगआउट — PASS
POST logout → लॉगिन पेज पर वापस (पासवर्ड इनपुट बॉक्स दिखता है)।

## समस्याएँ और फेल विश्लेषण

### समस्या 1 (गलत संकेत, दोष नहीं)：पेज सीधे खोलने पर `Cannot read properties of undefined (reading 'Account')`
- घटना：स्कैन के दौरान सीधे `/app/admin/xxx/index` खोलने पर permission.js में `window.Admin.Account` undefined।
- कारण：`window.Admin` केवल मुख्य फ्रेम index.html में इंजेक्ट होता है, सीधे सबपेज (बिना मुख्य फ्रेम) पर गायब।
- निष्कर्ष：वास्तविक उपयोग पथ (साइडबार क्लिक से iframe) में यह त्रुटि नहीं आती, दोष नहीं।

### समस्या 2 (वास्तविक छोटा दोष)：अवतार खाली होने पर `<img src="null">` से 404
- घटना：user सूची पेज लोड होते समय `/app/admin/user/null` अनुरोध → 404 कंसोल त्रुटि।
- मूल कारण：`admin/app/view/user/index.html:273` (admin/index.html में भी यही)：
  `'<img src="'+encodeURI(d['avatar'])+'" ...'` — पंक्ति avatar NULL होने पर `encodeURI(null)` → स्ट्रिंग `"null"`, ब्राउज़र सापेक्ष पथ से `/app/admin/user/null` हल करता है।
- प्रभाव：केवल अवतार खाली वाली पंक्तियों में टूटी छवि + 1 404 कंसोल लॉग, कार्यात्मक प्रभाव नहीं।
- सुझाव：`encodeURI(d['avatar'] ?? '')` या खाली मान पर img रेंडर न करें।

### समस्या 3 (वातावरण भिन्नता, दोष नहीं)：36 मॉडल `erik_*` टेबल की ओर इशारा करते हैं, डेटाबेस में मौजूद नहीं
- घटना：इस डेटाबेस की वास्तविक टेबलें `orders/products/...` हैं, जबकि `admin/app/model/` के 36 मॉडल `$table = 'erik_xxx'` हैं, जिससे इन सूची पेजों की टेबल में डेटा नहीं होता (पेज स्वयं 200 रेंडर सामान्य)।
- विवरण：अस्थायी `CREATE TABLE erik_* LIKE 基表` + e2e_ टेस्ट पंक्तियाँ डालकर सत्यापित किया कि ये पेज डेटा रेंडर श्रृंखला काम करती है, सत्यापन के बाद सभी हटा दिए गए (वर्तमान में `erik_%` टेबल 0)। यह नामकरण असंगति की वातावरणीय समस्या है, आगे एकरूप करने का सुझाव।

## टेस्ट वातावरण परिवर्तन विवरण (महत्वपूर्ण)

टेस्ट के दौरान मेरे द्वारा क्षतिग्रस्त `wa_*` अनुमति डेटा की मरम्मत और मेनू बहाली के लिए निम्न परिवर्तन किए गए, सभी को वापस उपयोग योग्य स्थिति में सत्यापित किया गया：

1. **wa_* टेबल बहाली** (पहले गलती से हटाई गईं, संरचना `install.sql` से पुनर्निर्मित)：wa_admins (admin/apitestadmin दोनों का पासवर्ड `Test@123456` रीसेट, मूल apitestadmin पासवर्ड अज्ञात)、wa_roles (id=1 SuperAdmin `*`)、wa_admin_roles、wa_options (system_config प्लगइन install.sql से बहाल)、wa_uploads、wa_users。
2. **wa_rules पुनर्निर्माण**：`admin/config/menu.php` के अनुसार पूर्ण upsert से 110 मेनू (अनुमति बिंदु सहित) बहाल, InstallController::importMenu तर्क की नकल।
3. **wa_rules.id AUTO_INCREMENT फिक्स**：`install.sql` में wa_rules.id परिभाषा में AUTO_INCREMENT गायब था (टेबल-निर्माण bug), `ALTER TABLE ... MODIFY id bigint unsigned NOT NULL AUTO_INCREMENT` किया गया।
4. **अस्थायी टेस्ट डेटा साफ**：erik_* कॉपी टेबल 0、e2e_ टेस्ट पंक्तियाँ 0 (wa_users/orders/products/suppliers/tickets सभी वापस साफ)।

> ⚠️ यदि apitestadmin का पासवर्ड मूल रूप से `Test@123456` नहीं था, तो अलग से रीसेट करना होगा। admin पासवर्ड अपरिवर्तित है।
