## तीन, गंभीर सुरक्षा समस्याएँ (P0 / P1)

### P0-1. Apple `id_token` बिना हस्ताक्षर सत्यापन — सीधे खाता अपहरण संभव
**फ़ाइल**: `service/app/user/service/OAuthService.php:180-192` (`appleProfile()`)

```php
$parts  = explode('.', $tokenData['id_token']);
$claims = json_decode(base64_decode($parts[1]), true);   // केवल base64 डिकोड, कोई हस्ताक्षर/iss/aud/exp सत्यापन नहीं
```

हमलावर स्वयं `id_token` बना सकता है, किसी भी email से OAuth लॉगिन पूरा कर सकता है। `resolveUser()` email के अनुसार मौजूदा उपयोगकर्ता से मिलाकर सीधे टोकन जारी करता है → **किसी भी खाते का अपहरण**।

**फिक्स**: Apple JWKS (`https://appleid.apple.com/auth/keys`) + `Firebase\JWT\JWT::decode($idToken, $keys, ['ES256'])` से हस्ताक्षर सत्यापन, और `iss=appleid.apple.com`, `aud=client_id`, `exp`, `nonce` की जाँच।

### P1-1. OAuth लॉगिन में `email_verified` सत्यापित नहीं
**फ़ाइल**: `OAuthService.php:163-178, 282-303`

Google/Facebook/Microsoft/LinkedIn सभी `email_verified` फ़ील्ड लौटाते हैं, कोड पूरी तरह अनदेखा करता है। प्रदाता पर बिना-सत्यापित-ईमेल वाले उपयोगकर्ता उस email से मौजूदा पंजीकृत खाते को बाँध/अपहरण कर सकते हैं। GitHub पथ `verified` सत्यापित करता है (सही), शेष प्रदाताओं पर एकीकृत सत्यापन आवश्यक।

### P1-2. रेट लिमिट मिडलवेयर मौजूद है लेकिन कभी माउंट नहीं हुआ — दस्तावेज़ और कार्यान्वयन असंगत
**फ़ाइलें**: `common/Security/RateLimitMiddleware.php` + `config/security.php` + `config/route.php`

- `security.php` में login=5/min, register=3/min आदि रेट लिमिट नियम कॉन्फ़िगर हैं
- `RateLimitMiddleware` **किसी भी रूट द्वारा संदर्भित नहीं** (पूरे रेपो के grep में केवल क्लास स्वयं मिलती है)
- `docs/features.md` दावा करता है लॉगिन "लिमिट 5 req/min", रजिस्ट्रेशन "लिमिट 3 req/min" — वास्तव में मौजूद नहीं
- ऐतिहासिक ऑडिट रिपोर्ट (`security-audit-2026-08-04.md`) ने इस आइटम को OK चिह्नित किया था, केवल कॉन्फ़िगरेशन देखा, माउंट सत्यापित नहीं किया — इस दौर में सुधारा गया

**प्रभाव**: लॉगिन/रजिस्ट्रेशन/फॉरगॉट-पासवर्ड/रिसेट-पासवर्ड/रिकवरी कोड/कैप्चा आदि सार्वजनिक एंडपॉइंट्स पर असीमित ब्रूट-फोर्स संभव (लॉगिन केवल per-account लॉक पर निर्भर, क्रेडेंशियल स्टफिंग और IP-स्तरीय फ्लडिंग नहीं रोकता)।

**फिक्स**: `RateLimitMiddleware` को `/api/auth/*`, `/api/captcha/*` आदि सार्वजनिक रूट्स पर माउंट करें (वैश्विक `''` समूह पर लगा सकते हैं, `route` पैरामीटर से भेद करें)।

### P1-3. TOTP 2FA लॉगिन प्रक्रिया में अनिवार्य नहीं
**फ़ाइलें**: `AuthService.php:64-97` (`login()`) + `AuthController.php` + `config/features.php`

`user->totp_enabled` केवल `totpVerify/totpDisable/totpRecoveryCodes` में जाँचा जाता है, **`login()` कभी सत्यापित नहीं करता**। 2FA सक्षम उपयोगकर्ता केवल पासवर्ड से ही वैध access token प्राप्त करता है — 2FA बेकार है (`FEATURE_TOTP` डिफ़ॉल्ट रूप से चालू)।

**फिक्स**: लॉगिन के समय यदि `totp_enabled` है, तो अस्थायी टोकन जारी करें और TOTP सत्यापन पास होने पर ही नियमित टोकन बदलें (या totp code पैरामीटर अनिवार्य करें)।

### P1-4. नोटिफिकेशन चैनल प्लेसहोल्ड कार्यान्वयन — ईमेल सत्यापन/पासवर्ड रीसेट प्रोडक्शन में अनुपयोगी
**फ़ाइलें**: `app/Notification/Queue/EmailSender.php`, `SmsSender.php`, `PushSender.php`

तीनों कंज्यूमर केवल `error_log()` से सिमुलेट करते हैं, और `send_status` को `sent` दर्ज करते हैं। परिणाम:
- **फॉरगॉट-पासवर्ड फ्लो टूटा**: `AuthController::forgotPassword()` सत्यापन कोड उत्पन्न कर "ईमेल" भेजता है, लेकिन ईमेल कभी नहीं पहुँचता → उपयोगकर्ता स्वयं पासवर्ड रीसेट नहीं कर सकता
- रजिस्ट्रेशन ईमेल सत्यापन, नए IP लॉगिन अलर्ट भी उसी तरह अप्रभावी
- `.env.example` में `SMTP_*`/`MAIL_FROM_*` कुल 7 वेरिएबल का कोई कोड पढ़ता नहीं (मृत कॉन्फ़िगरेशन)

**फिक्स**: वास्तविक ईमेल भेजना जोड़ें (PHPMailer/SendGrid SDK), भ्रामक `sent` स्थिति चिह्न हटाएँ; या स्पष्ट रूप से अपूर्ण सुविधा चिह्नित कर दस्तावेज़ों से संबंधित वादे हटाएँ।

## छह, ऑप्टिमाइज़ेशन सुझाव (गैर-अवरोधक)

1. **DI-आधारित सेवा निर्माण**: `AuthController` कंस्ट्रक्टर सीधे `new AuthService()/OAuthService()` करता है, कंटेनर से जोड़ने का सुझाव (webman नेटिव समर्थन), परीक्षण और प्रतिस्थापन आसान।
2. **अपलोड निर्देशिका सख्तीकरण**: निर्देशिका में `index.html` रखें, PHP निष्पादन अक्षम करें (nginx `location ~ \.php { deny all; }`)।
3. **WAF रेगेक्स समेकन**: `security.php` का `sqli_patterns` `\b(select|update|delete|...)\b` जैसे व्यापक पैटर्न रखता है, वैश्विक लिमिटिंग में उपयोगकर्ता टिकट/समीक्षाओं में इन शब्दों के आने पर गलत 403 हो सकता है; केवल संवेदनशील पैरामीटर्स पर प्रभावी करें या रेगेक्स कसें।
4. **लॉग ऑडिट**: `AuditLogger::record('user_registered', ['user_id' => null])` नया उपयोगकर्ता ID दर्ज नहीं करता, वास्तविक ID दर्ज करने का सुझाव।
5. **OAuth टेस्ट कवरेज**: `OAuthServiceTest` URL निर्माण और code एक्सचेंज कवर करता है, लेकिन `resolveUser()` (DB पथ) और Apple हस्ताक्षर सत्यापन पथ पर कोई परीक्षण नहीं; P0 फिक्स के बाद हस्ताक्षर-विफल परीक्षण मामले अनिवार्य रूप से जोड़ें।
6. **CI इंटीग्रेशन**: प्रोजेक्ट में `.github` निर्देशिका है, GitHub Actions जोड़ने का सुझाव: `composer install && phpunit` + `composer audit`, रिग्रेशन रोकथाम।
7. **HTTP विधि बाध्यता**: OAuth रूट्स पर GET/POST callback दोनों पंजीकृत होना उचित है (Apple को आवश्यक), शेष सार्वजनिक राइट ऑपरेशन स्पष्ट रूप से POST हैं, OK।
