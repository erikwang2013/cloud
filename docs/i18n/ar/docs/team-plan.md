## 2. قائمة المتبقيات والمخاطر (مراجعة 2026-08-17)

### 2.1 بنود حاجبة للنشر (أولوية عالية)

- **فجوة بيئة DB_PASSWORD**: service/.env سلسلة فارغة → جميع نقاط نهاية قاعدة البيانات تعيد 500، وهي السبب الجذري لـ 9+1 اختبار تخطٍ. ليست مشكلة كود، تتطلب ملء القيمة من التشغيل (قالب موجود في .env.example الجذر)
- **غياب سقالات مشروع HarmonyOS**: apps/harmonyos تحتوي 3 ملفات .ets فقط (LoginPage/AuthManager/ApiClient)، وتنقص كل إعدادات مشروع hvigor/DevEco → لا يمكن البناء؛ أبلغ فحص harmonyos-check في CI بصدق (exit 1)

### 2.2 انحرافات التوثيق عن الكود (4 بنود معلقة من P1)

- فلترة status في GET /api/v1/orders غير منفذة
- أحداث دفع WebSocket مفقودة (وثائق websocket_push تعلن عنها)
- نطاق إطلاق ticket.updated غير واضح
- product_attributes schema ميت (لا يستخدمه أي كود)

### 2.3 بنود مراقبة مالية/أمنية (سجل مراجعة ثنائي، مستوى منخفض)

- **الطلبات بلا مفتاح تكرار**: إعادة إرسال نفس السلة قد تولد طلبين مزدوجين (متوسط، يُقترح جدولته)
- تقييم الموردين لا يتحقق من ملكية/حالة الطلب
- اقتطاع fee عبر bcmath (المنزلة العشرية الخامسة، اتجاه خصم أقل من 0.0001/عملية؛ متسق مع التوجيه دون انحراف تسوية)
- WAF يقرأ جسم multipart الكبير خامًا (سيناريو json مغطى بـ $input، multipart طبقة دفاع إضافية)
- user_coupons بلا قيد فريد (دلاليًا يُسمح بعدة صفوف لعدة طلبات لمستخدم واحد، ملاحظة)
- nginx-admin بدون CSP (admin واجهة Layui أمامية تتضمن سكربتات مضمّنة، يُبقى على الوضع الحالي)

### 2.4 عدم اتساق نموذج الصلاحيات (اكتشاف جديد في P2، بانتظار التقليص)

- 6 معرفات صلاحيات DB-only / 19 Rbac-only / اختلافات توزيع الأدوار (support/supplier)
- AdminRoleMiddleware يستبعد finance بينما يعرّف Rbac.php دور finance
