## Problèmes de code métier découverts (non modifiés, consignés selon les contraintes)

1. **Alert.context doublement encodé** : `AlertEngine::trigger()` passe une chaîne `json_encode($context)` à `Alert::create`, or le modèle Alert a un cast `array` sur `context`, et setAttribute ré-encode en JSON → la valeur en base est doublement encodée, et à la relecture `$alert->context` est une chaîne JSON **au lieu d'un tableau** (`app/Monitor/Service/AlertEngine.php` + `app/Monitor/Model/Alert.php:20`). Le test asserte le comportement réel et le commente. Suggestion : AlertEngine doit passer un tableau.
2. **Double point dans le register de domaines** : `DomainService::register()` concatène `$domainName . '.' . $tld`, or la table de config tld stocke le point (`.com`) → génère `example..com` (`app/Domain/Service/DomainService.php:40`). Le test asserte le comportement réel et le commente. Suggestion : retirer le point du tld avant concaténation.

## Lacunes restantes et raisons

| Lacune | Raison |
|------|------|
| collectAllMetrics / checkDowntime / checkSslCertificates de ResourceMonitor | Dépendent de Redis + ProviderFactory (appels de provider réels) et de la sonde de socket TLS ; exigent une couche de mock ou un environnement d'intégration, coût de test unitaire élevé |
| Chemin ES principal de ProductService (searchKeywordIds touchant ES) | Nécessite un vrai conteneur ES (le ProductSearchTest existant est déjà markTestSkipped avec les étapes indiquées) ; l'environnement de test unitaire n'a pas de moteur scout dans son conteneur, `Product::search` renvoie un tableau vide sans lever d'exception, la branche de dégradation SQL ne peut pas être déclenchée en unitaire |
| Rendu de modèles NotificationDispatcher (getLocalizedTitle/body) | Le NotificationDispatcherTest existant couvre déjà le chemin de base ; le rendu multilingue des modèles relève de la couche I18n |
| Exécution des resolvers Graphql (products renvoyant de vraies réponses) | Les resolvers dépendent des modèles Product/Resource/Order ; la structure du schéma est couverte, le chemin d'exécution est suggéré en tests d'intégration API |
