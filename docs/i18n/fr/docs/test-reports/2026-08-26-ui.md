## 3. Problèmes bloquants (par ordre de dépendance)

### B1. Le format de ENCRYPTION_MASTER_KEY ne correspond pas à l'exigence du code → les workers admin plantent au démarrage
- **Phénomène** : après `php start.php start`, les 4 workers sortent tous sur exception (le port reste ouvert mais les requêtes ne reçoivent jamais de réponse, les connexions s'accumulent dans le backlog accept) ; log :
  `InvalidArgumentException: Master key must be exactly 32 bytes. in vendor/erikwang2013/encryption/src/EncryptionManagerFactory.php:29`
- **Cause racine** : `ENCRYPTION_MASTER_KEY=y1Odnbg50NHEvvLHGb8aexKqy8AQ7izm0x+yoEgrYCU=` dans `admin/.env` est un **base64 de 44 octets** ; or `EncryptionManagerFactory::fromMasterKey()` exige **32 octets bruts** (le commentaire de `admin/config/encryption.php:30` mentionne aussi « 64 hex characters »). Mais `.env.example:64` l'étiquette base64 — la configuration et la convention du code se contredisent.
- **Complément** : `support/bootstrap.php:47` utilise `Dotenv::createUnsafeMutable()->load()`, **les écrasements d'env au niveau processus sont écrasés par les valeurs de .env**, impossible de contourner par les paramètres de lancement (testé deux fois, échec).
- Le décodage base64 de cette clé donne exactement 32 octets (hex `cb539d9d…6025`) : le format correct = la valeur décodée du base64.

### B2. `config/database.php` manquant → la couche base de données n'existe pas
- **Phénomène** : `/account/login` → 500 `BusinessException: 请重启webman` (`checkDatabaseAvailable()` à `app/controller/AccountController.php:263`, levé si `!config('database')`).
- **Cause racine** : ce fichier est généré par l'assistant d'installation et gitignoré, il n'a jamais existé dans le dépôt (`git ls-files` sans trace). `config/thinkorm.php` manque également.

### B3. `install.sql` manquant → l'assistant d'installation ne peut pas s'exécuter
- **Phénomène** : le `step1` de l'assistant (`InstallController.php:105`) vérifie `base_path().'/install.sql'`, s'il manque il renvoie « fichier SQL de base de données inexistant ». Le fichier n'existe pas dans le dépôt.
- Impact : la seule voie officielle pour corriger B2 (assistant UI) est également bloquée.

### B4. Tous les chemins de ressources statiques des vues utilisent le préfixe `/app/admin/`, sans aucun mapping de ce préfixe → tout l'UI sans style, JS en 404
- **Phénomène** (mesuré sur page de login/page d'installation/cadre principal) : `/app/admin/component/pear/css/pear.css`, `/app/admin/admin/css/reset.css`, `/app/admin/component/layui/layui.js` etc. renvoient tous 404 ; `ReferenceError: layui is not defined` ; les formulaires ne peuvent pas être soumis.
- **Cause racine** : les fichiers statiques se trouvent en réalité dans `public/admin/`, `public/component/` (webman les sert sous `/admin/...`, 200 mesuré) ; or `app/view/account/login.html`, `app/view/index/install.html`, `app/view/index/index.html` etc. référencent tous `/app/admin/...`. `config/route.php` n'a que 4 routes explicites `/app/admin/` (captcha/dict/dashboard-data/table-export), `config/static.php` n'a aucun mapping de préfixe, et `docker/nginx.conf` comme `docker/nginx-admin.conf` n'ont pas de `location /app/admin`. La convention d'URL frontale et back-end est globalement incohérente (le POST du formulaire `/app/admin/account/login` → 404 ; le endpoint réel devrait être à la racine `/account/login`).

### B5. La cible de redirection non-connecté est erronée → toutes les pages métier deviennent des pages 404 Chrome
- **Phénomène** (mesuré sur /user/index, /order/index, /product/index, /supplier/index, /config/index, /role/index, /admin/index, /ticket/index, /index/dashboard, /dashboard/index) : renvoient 200, mais la page est redirigée par JS vers `http://127.0.0.1:8788/app/admin` → cette URL renvoie 404 → rendu de la page « page introuvable » de Chrome.
- **Cause racine** : `app/middleware/AccessControl.php:45` renvoie `admin_error_401_script()` (`app/functions.php:93`) pour les non-connectés, dont le contenu est `<script>top.location.href = '/app/admin';</script>` — l'URL de la page de login est codée en dur en `/app/admin`, même erreur de convention de chemin que B4.
- Au passage : `/payment_channel/index`, `/coupon/index`, `/domain_tld/index`, `/dns_zone/index`, `/invoice/index`, `/report/index` renvoient directement `ERR_HTTP_RESPONSE_CODE_FAILURE` (échec au niveau contrôleur/routes, la redirection n'est pas atteinte).

### B6. 500 sur le chemin racine : données `system_config` manquantes
- **Phénomène** : après avoir complété manuellement la configuration B2, `GET /` (point d'entrée de rendu de la page de login `IndexController::index`) → 500 `ErrorException: json_decode(): Passing null to parameter #1 … in app/controller/IndexController.php:49`.
- **Cause racine** : `Option::where('name','system_config')->value('value')` renvoie null (aucune ligne dans la base — celle-ci n'a pas été produite par l'assistant d'installation), `json_decode(null)` déclenche la dépréciation PHP 8.3 et lève. La page de login plante donc directement si les données n'ont pas été initialisées par l'assistant.

## 5. Récapitulatif des défauts UI découverts

### Première passe (état d'origine, bloquants)

1. **B1 (bloquant)** la clé principale .env en base64 ne correspond pas à l'exigence de 32 octets du code → le service ne démarre pas du tout. Reproduction : `cd admin && php start.php start -d`.
2. **B2/B3 (bloquants)** artefacts d'installation manquants (config/database.php, install.sql), et l'assistant lui-même ne peut pas s'exécuter → l'application ne peut pas être initialisée.
3. **B4 (bloquant)** les chemins de ressources des vues du site `/app/admin/...` ne correspondent pas à l'emplacement réel des fichiers statiques/préfixe de routes → sans style, sans JS, formulaires inutilisables.
4. **B5 (bloquant)** la redirection 401 non-connecté est codée en dur sur `/app/admin` → toutes les pages métier sautent sur un lien mort.
5. **B6** le rendu de la page de login n'a aucun repli si la ligne `system_config` manque, `json_decode(null)` renvoie directement 500 (la dépréciation PHP 8.3 est promue en exception).

### Seconde passe (mesurée après login, problèmes systémiques)

6. **W1. WAF bloque à tort des URL métier** : `admin/app/middleware/WafMiddleware.php:75` applique un scan regex SQLi/XSS sur le chemin de l'URL (`config/security.php` : `\b(union|select|insert|update|delete|drop|...)\b`, `\balert\b` etc.) :
   - `/alert/index` atteint la règle XSS car l'URL contient « alert » → **403** ;
   - tous les endpoints de données CRUD (`/user/select`, `/user/insert`, `/user/update`, `/user/delete`, `/order/select`…) atteignent `\bselect\b` et d'autres règles SQLi → **403**.
   - Impact : **le chargement des données de toutes les pages de listes et les ajouts/suppressions/modifications sont entièrement inutilisables dans le navigateur** (les requêtes frontales `SELECT_API` renvoient toutes 403).
7. **W2. La convention URL à souligné ne tient pas + tous les liens de menu sont morts** : le routage automatique de webman ne supporte pas le souligné dans les noms de contrôleurs — `/order_item/index` 404, `/orderitem/index` 200 (les 47 pages ne sont atteignables qu'avec des URL camelCase). Mais tous les href de `config/menu.php` et `config/business_menu.php` sont en `/app/admin/<snake_case>/index` (ex. `/app/admin/payment_channel/index`) → **chaque élément de la navigation latérale est un lien mort (404 ou 403)**.
8. **W3. La constante JS des tableaux de données SELECT_API n'est pas définie** : les constantes `SELECT_API`/`INSERT_API` référencées par le JS des pages (`/app/admin/...` 404, résidu de B4) ne sont pas injectées → les tableaux des pages de listes ne rendent aucune donnée, ni pagination ni recherche.
9. **W4. 11 à 15 erreurs console 404 de ressources statiques par page** : impact continu de B4 — les 47 pages en 200 sont toutes sans style, `layui is not defined`, formulaires et fenêtres modales inutilisables.

**Résumé** : le squelette des pages se rend (47/51), mais la navigation latérale (W2), le chargement des données de tableaux (W3+W1) et toutes les écritures CRUD (W1) sont inutilisables dans le navigateur — le panneau est en pratique inopérant.

## 6. Pages non testées et raisons

- **Écritures CRUD (soumissions de formulaires ajout/modification/suppression)** : tous les endpoints de données sont interceptés par le WAF (W1) + le JS des formulaires est inutilisable (B4/W3), aucune écriture ne peut être effectuée via l'UI. Si W1 et B4 sont corrigés, des tests complémentaires peuvent couvrir les endpoints `insert/update/delete`.
- **Pages après connexion** : toutes mesurées en seconde passe (47/51 rendues avec succès, voir §4.2) ; seuls restent non couverts les sauts de menu (liens morts W2) et le chargement des données de tableaux (W1/W3).
- **apps/ (clients Flutter/HarmonyOS)** : exigent un appareil réel/émulateur, hors périmètre de cette passe (concentrée sur le Web comme convenu dans la tâche).
- **Pages d'API métier service** : pas d'UI Web (8787 `/` et `/install.php` renvoient tous deux 404, API pure), les tests au niveau interface sont couverts par la tâche #13.

## 7. État actuel de l'environnement et suggestions de correctifs

- **Modifications de la base de test (autorisées par l'utilisateur, à noter)** :
  - le mot de passe du compte `admin` de `wa_admins` a été **temporairement réinitialisé à `Test@123456`** (base de test locale uniquement), prière de le rétablir rapidement ;
  - la ligne `system_config` a été insérée dans `wa_options` (correctif B6, opération sur la base de test).
- Le 8788 actuel est servi par l'instance de copie `/tmp/cp-admin-ui` (bootstrap passe, DB connectée). L'instance d'origine du dépôt est arrêtée (ses workers plantent au démarrage). Différences de la copie : la clé principale `/tmp/cp-admin-ui/.env` est passée à la valeur brute de 32 octets ; `config/database.php`/`thinkorm.php` ont été générés (pointant vers la même base `cloud_platform`). **Pour restaurer le service natif du dépôt : corriger d'abord B1 (.env, clé principale en 32 octets décodés), puis arrêter l'instance /tmp avant de démarrer l'instance du dépôt.**
- Priorité de correctif suggérée : B1 (une ligne de changement .env) → B2/B3 (faire passer/compléter les artefacts d'installation) → B4/B5 (unifier les préfixes d'URL des vues et redirections, ou ajouter le mapping statique `/app/admin`) → B6 (repli si Option manquante) → W1 (WAF limité au scan du corps de requête/paramètres, en sautant le chemin d'URL et les noms de contrôleurs simples) → W2 (href des menus au format `/{controller}/index` sans préfixe ; retirer au passage le souligné).
- Attention : si `.env` est dans git (ce dépôt contient des traces de commit le concernant), il devrait être ajouté à .gitignore ; la clé principale est suggérée en injection d'env plutôt qu'en clair dans le dépôt.
