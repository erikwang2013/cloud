## Bug réel exposé et corrigé

**`HealthRegistry::with_check` appelle `blocking_write()` dans le runtime tokio et panique** (`Cannot block the current thread from within a runtime`).
- Déclenchement : les tests au niveau route appellent `with_check` en chaîne dans `#[tokio::test]` (auparavant seuls des tests synchrones l'appelaient, jamais exposé).
- Correctif : passage à `pub async fn with_check` + `self.checks.write().await` (changement minimal, `ecat-health/src/lib.rs:28`).
- Impact : aucun appelant en code de production (grep : utilisé uniquement par les tests du crate), l'API passe de synchrone à async, correction sans risque.
