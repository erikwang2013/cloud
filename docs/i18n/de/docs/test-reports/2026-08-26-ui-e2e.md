## 问题与失败分析

### 问题 1（伪报，非缺陷）：直连页面时 `Cannot read properties of undefined (reading 'Account')`
- 现象：扫描时直连 `/app/admin/xxx/index`，permission.js 报 `window.Admin.Account` undefined。
- 原因：`window.Admin` 只在主框架 index.html 注入，直连子页（无主框架）时缺失。
- 结论：真实使用路径（侧边栏点击进 iframe）无此报错，非缺陷。

### 问题 2（真实小缺陷）：头像为空时 `<img src="null">` 触发 404
- 现象：user 列表页加载时请求 `/app/admin/user/null` → 404 控制台错误。
- 根因：`admin/app/view/user/index.html:273`（admin/index.html 同款）：
  `'<img src="'+encodeURI(d['avatar'])+'" ...'` — 行 avatar 为 NULL 时 `encodeURI(null)` → 字符串 `"null"`，浏览器按相对路径解析成 `/app/admin/user/null`。
- 影响：仅头像为空的行显示破图 + 1 条 404 控制台日志，无功能影响。
- 建议：`encodeURI(d['avatar'] ?? '')` 或空值不渲染 img。

### 问题 3（环境差异，非缺陷）：36 个模型指向 `erik_*` 表，库中不存在
- 现象：本库真实表为 `orders/products/...`，而 `admin/app/model/` 中 36 个模型 `$table = 'erik_xxx'`，导致这些列表页表格无数据（页面本身 200 渲染正常）。
- 说明：已通过临时 `CREATE TABLE erik_* LIKE 基表` + 插入 e2e_ 测试行验证这些页面数据渲染链路可用，验证后已全部删除（当前 `erik_%` 表 0 张）。这是命名不一致的环境问题，建议后续统一。
