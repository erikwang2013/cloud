## Problemas e Análise de Falhas

### Problema 1 (falso positivo, não é defeito): `Cannot read properties of undefined (reading 'Account')` em acesso direto
- Sintoma: ao acessar diretamente `/app/admin/xxx/index` na varredura, o permission.js reporta `window.Admin.Account` undefined.
- Causa: `window.Admin` só é injetado pelo index.html do framework principal; ausente no acesso direto a subpáginas (sem o framework).
- Conclusão: o caminho real de uso (clique na barra lateral entrando no iframe) não apresenta esse erro; não é defeito.

### Problema 2 (defeito real menor): `<img src="null">` dispara 404 quando o avatar está vazio
- Sintoma: ao carregar a lista de user, é feita requisição a `/app/admin/user/null` → erro de console 404.
- Causa raiz: `admin/app/view/user/index.html:273` (mesmo padrão em admin/index.html):
  `'<img src="'+encodeURI(d['avatar'])+'" ...'` — quando avatar da linha é NULL, `encodeURI(null)` → string `"null"`, que o navegador resolve como caminho relativo `/app/admin/user/null`.
- Impacto: apenas linhas com avatar vazio mostram imagem quebrada + 1 log de console 404; sem impacto funcional.
- Sugestão: `encodeURI(d['avatar'] ?? '')` ou não renderizar o img quando o valor é vazio.

### Problema 3 (diferença de ambiente, não é defeito): 36 modelos apontam para tabelas `erik_*`, inexistentes no banco
- Sintoma: as tabelas reais deste banco são `orders/products/...`, mas 36 modelos em `admin/app/model/` têm `$table = 'erik_xxx'`, fazendo essas páginas de lista renderizarem tabelas sem dados (a página em si renderiza 200 normalmente).
- Observação: via `CREATE TABLE erik_* LIKE tabela base` temporário + inserção de linhas de teste e2e_, a cadeia de renderização de dados dessas páginas foi validada como funcional; tudo foi excluído após a validação (hoje, 0 tabelas `erik_%`). É um problema de ambiente por inconsistência de nomenclatura; sugere-se unificar depois.

- O captcha é lido de `runtime/sessions/session_<PHPSID>`; requer php CLI executável.
