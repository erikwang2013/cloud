## Detalhes das Falhas
- `POST /api/auth/register(criptografado)` [auth-flow] status=-1 esperado=0 observação: code=-1 msg= dentro do envelope=Server internal error —— o cast Encryptable do modelo User está sem a chave de 16 bytes (aes-128-ecb), criar usuário já retorna 500 (defeito da aplicação)
- `POST /api/auth/register(texto puro)` [auth-flow] status=500 esperado=200 observação: HTTP 500 body=Server internal error —— chave Encryptable ausente (defeito da aplicação)
- `POST /api/auth/login` [auth-flow] status=200 esperado=200 observação: code=401 msg=Invalid credentials —— o defeito de registro bloqueia a cadeia completa de login (CAPTCHA de uso único, reuso retorna 422)

## Observações e Limitações
- Pagamento Stripe é serviço externo: `POST /api/orders/{id}/pay` apenas valida caminhos de erro (4xx/5xx), não é possível concluir pagamento real
- Endpoints `/admin/api/*` do service: token de usuário comum deve retornar 401/403 (AdminRole/RBAC), token de administrador exige conta de admin no service (não configurada neste ambiente)
- Problema da chave mestra do admin (B1) corrigido e retestado: 8788 inicia normalmente, todas as rotas captcha/dashboard/dict/export/login/CRUD disponíveis (cópia atualizada com o arquivo de rotas completo)
- Painel admin (cópia 8788): todas as rotas disponíveis, a cadeia de login (captcha+session+bcrypt) retorna token com sucesso; item de observação: listas user/order/product/config acessíveis sem cookie de sessão (HTTP 200, sem autenticação)
- Registro (ambos os caminhos do service retornam 500): o cast Encryptable do modelo User está sem a chave de 16 bytes (aes-128-ecb, MissingEncryptionKeyException) → registro indisponível, impossível obter token de usuário, casos autenticados com token foram pulados; o login só pôde validar caminhos de erro 401/422 (CAPTCHA de uso único + nenhum usuário para logar)
- Endpoints públicos: nesta rodada de reteste, products/{id}, help/{slug}, stripe webhook, domain/* voltaram todos ao normal (problemas anteriores de ModelNotFoundException 500 e colunas ausentes em domain_tlds já corrigidos)
- Limitação de taxa: padrão de 60 req/60s por IP, testes respeitaram intervalo de 1s, 429 esporádicos são esperados
- WAF (plugin security-php): o detector dns_rebinding classifica Host=127.0.0.1 como endereço interno e bloqueia por engano (problema de configuração da aplicação, escopo W1-W3); este conjunto contorna enviando Host de domínio via variável de ambiente `TEST_HOST` (formato de implantação real); o bloqueio automático de IP (max_attempts=5) usa armazenamento em arquivo, liberado automaticamente 15 minutos após o tráfego de teste
