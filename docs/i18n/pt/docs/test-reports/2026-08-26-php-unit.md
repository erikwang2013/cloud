## Problemas no Código de Negócio Encontrados (não modificados, registrados conforme a restrição)

1. **Double encoding de Alert.context**: `AlertEngine::trigger()` passa a string `json_encode($context)` para `Alert::create`, mas o modelo Alert tem cast `array` em `context`; o setAttribute faz json_encode de novo → grava com double encoding; ao ler, `$alert->context` é uma **string** JSON em vez de array (`app/Monitor/Service/AlertEngine.php` + `app/Monitor/Model/Alert.php:20`). O teste assere o comportamento real e comenta. Sugestão: AlertEngine passar array.
2. **Ponto duplo no domínio em Domain register**: `DomainService::register()` concatena com `$domainName . '.' . $tld`, mas a tabela de configuração de tld armazena com ponto `.com` → gera `example..com` (`app/Domain/Service/DomainService.php:40`). O teste assere o comportamento real e comenta. Sugestão: remover o ponto do tld antes de concatenar.

## Lacunas Remanescentes e Motivos

| Lacuna | Motivo |
|------|------|
| collectAllMetrics / checkDowntime / checkSslCertificates do ResourceMonitor | Dependem de Redis + ProviderFactory (chamadas reais de provider) e sondagem de socket TLS; exigem camada de mock ou ambiente de integração, custo alto para teste unitário |
| Caminho principal de ES no ProductService (searchKeywordIds acertando o ES) | Exige container ES real (ProductSearchTest existente já tem markTestSkipped com os passos); no ambiente de teste unitário não há scout engine, `Product::search` retorna array vazio sem lançar exceção, e o ramo de degradação SQL não pode ser disparado em teste unitário |
| Renderização de templates do NotificationDispatcher (getLocalizedTitle/body) | NotificationDispatcherTest existente já cobre o caminho básico; renderização multilíngue de templates pertence à camada I18n |
| Execução dos resolvers Graphql (products retornando dados reais) | Resolvers dependem dos modelos Product/Resource/Order; a estrutura do Schema já está coberta, o caminho de execução sugere teste de integração de API |
