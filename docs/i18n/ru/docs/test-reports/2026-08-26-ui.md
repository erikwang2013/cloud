## 3. 阻断问题（按依赖顺序）

### B1. ENCRYPTION_MASTER_KEY 格式与代码要求不符 → admin worker 启动即崩溃
- **现象**：`php start.php start` 后 4 个 worker 全部抛异常退出（端口挂着但请求永不响应，连接堆积在 accept backlog）；日志：
  `InvalidArgumentException: Master key must be exactly 32 bytes. in vendor/erikwang2013/encryption/src/EncryptionManagerFactory.php:29`
- **根因**：`admin/.env` 的 `ENCRYPTION_MASTER_KEY=y1Odnbg50NHEvvLHGb8aexKqy8AQ7izm0x+yoEgrYCU=` 是 **44 字节 base64**；而 `EncryptionManagerFactory::fromMasterKey()` 要求 **32 字节原始字节**（`admin/config/encryption.php:30` 注释亦写"64 hex characters"）。`.env.example:64` 却标注 base64——配置与代码约定矛盾。
- **补充**：`support/bootstrap.php:47` 用 `Dotenv::createUnsafeMutable()->load()`，**进程级 env 覆盖会被 .env 值覆盖**，无法用启动参数绕过（实测两次均失败）。
- 该 key 的 base64 解码结果恰为 32 字节（hex `cb539d9d…6025`），即正确格式 = base64 解码后的值。

### B2. `config/database.php` 缺失 → 数据库层不存在
- **现象**：`/account/login` → 500 `BusinessException: 请重启webman`（`app/controller/AccountController.php:263` `checkDatabaseAvailable()`，`!config('database')` 即抛出）。
- **根因**：该文件由安装向导生成且被 gitignore，仓库中从未存在（`git ls-files` 无记录）。同缺 `config/thinkorm.php`。

### B3. `install.sql` 缺失 → 安装向导无法执行
- **现象**：向导 `step1`（`InstallController.php:105`）检查 `base_path().'/install.sql'`，缺失则返回"数据库SQL文件不存在"。文件在仓库中不存在。
- 影响：修复 B2 的唯一官方路径（UI 向导）也走不通。

### B4. 全部视图静态资源路径使用 `/app/admin/` 前缀，但该前缀无任何映射 → 全 UI 无样式、JS 404
- **现象**（登录页/安装页/主框架实测）：`/app/admin/component/pear/css/pear.css`、`/app/admin/admin/css/reset.css`、`/app/admin/component/layui/layui.js` 等全部 404；`ReferenceError: layui is not defined`；表单无法提交。
- **根因**：静态文件实际位于 `public/admin/`、`public/component/`（webman 以 `/admin/...` 提供服务，实测 200）；而 `app/view/account/login.html`、`app/view/index/install.html`、`app/view/index/index.html` 等全部引用 `/app/admin/...`。`config/route.php` 仅有 4 条显式 `/app/admin/` 路由（captcha/dict/dashboard-data/table-export），`config/static.php` 无前缀映射，`docker/nginx.conf` 与 `docker/nginx-admin.conf` 亦无 `location /app/admin`。前端与后端 URL 约定整体不一致（表单 POST `/app/admin/account/login` → 404；实际端点应在根路径 `/account/login`）。

### B5. 未登录重定向目标错误 → 业务页全部变成 Chrome 404 页
- **现象**（/user/index、/order/index、/product/index、/supplier/index、/config/index、/role/index、/admin/index、/ticket/index、/index/dashboard、/dashboard/index 实测）：返回 200，但页面被 JS 重定向到 `http://127.0.0.1:8788/app/admin` → 该 URL 404 → 渲染 Chrome "找不到网页" 页。
- **根因**：`app/middleware/AccessControl.php:45` 未登录返回 `admin_error_401_script()`（`app/functions.php:93`），内容为 `<script>top.location.href = '/app/admin';</script>`——登录页地址写死 `/app/admin`，与 B4 同源的路径约定错误。
- 附带：`/payment_channel/index`、`/coupon/index`、`/domain_tld/index`、`/dns_zone/index`、`/invoice/index`、`/report/index` 直接 `ERR_HTTP_RESPONSE_CODE_FAILURE`（控制器/路由层即失败，未走到重定向）。

### B6. 根路径 500：`system_config` 数据缺失
- **现象**：在手动补齐 B2 配置后，`GET /`（登录页渲染入口 `IndexController::index`）→ 500 `ErrorException: json_decode(): Passing null to parameter #1 … in app/controller/IndexController.php:49`。
- **根因**：`Option::where('name','system_config')->value('value')` 返回 null（库中无该行——本库并非由向导安装产生），`json_decode(null)` 在 PHP 8.3 触发 deprecation 并抛错。即登录页在数据未按向导初始化时直接崩溃。

## 5. 发现的 UI 缺陷汇总

### 第一轮（环境原状，阻断）

1. **B1（阻断）** `.env` 主密钥 base64 与代码 32 字节要求不符 → 服务完全起不来。复现：`cd admin && php start.php start -d`。
2. **B2/B3（阻断）** 安装产物缺失（config/database.php、install.sql），且向导本身无法执行 → 应用无法初始化。
3. **B4（阻断）** 全站视图资源路径 `/app/admin/...` 与静态文件实际位置/路由前缀不一致 → 无样式、无 JS、表单不可用。
4. **B5（阻断）** 未登录 401 重定向写死 `/app/admin` → 所有业务页跳死链。
5. **B6** 登录页渲染对 `system_config` 行缺失无兜底，`json_decode(null)` 直接 500（PHP 8.3 deprecation 升级为异常）。

### 第二轮（登录后实测，系统性问题）

6. **W1. WAF 误杀业务 URL**：`admin/app/middleware/WafMiddleware.php:75` 对 URL path 做 SQLi/XSS 正则扫描（`config/security.php`：`\b(union|select|insert|update|delete|drop|...)\b`、`\balert\b` 等）：
   - `/alert/index` 因 URL 含 "alert" 命中 XSS 规则 → **403**；
   - 全部 CRUD 数据端点（`/user/select`、`/user/insert`、`/user/update`、`/user/delete`、`/order/select`…）命中 `\bselect\b` 等 SQLi 规则 → **403**。
   - 影响：**所有列表页数据加载与增删改在浏览器中完全不可用**（前端 `SELECT_API` 请求均 403）。
7. **W2. URL 下划线约定不成立 + 菜单链接全死**：webman 自动路由不支持控制器名下划线——`/order_item/index` 404，`/orderitem/index` 200（47 个页面全部用 camelCase 拼接 URL 才可达）。但 `config/menu.php` 与 `config/business_menu.php` 的全部 href 都是 `/app/admin/<snake_case>/index`（如 `/app/admin/payment_channel/index`）→ **侧边导航每一项都是死链（404 或 403）**。
8. **W3. 表格数据 JS 常量 SELECT_API 未定义**：页面 JS（`/app/admin/...` 404，B4 残留）引用的 `SELECT_API`/`INSERT_API` 等常量未注入 → 列表页表格渲染无数据、无法分页/搜索。
9. **W4. 每页 11-15 个静态资源 404 控制台错误**：B4 的持续影响面——47 个 200 页面全部无样式、`layui is not defined`，表单与弹窗不可用。

**总结**：页面骨架可渲染（47/51），但侧边导航（W2）、表格数据加载（W3+W1）、全部 CRUD 写操作（W1）在浏览器中均不可用——后台实质无法操作。

## 6. 未测页面与原因

- **CRUD 写操作（新增/编辑/删除表单提交）**：数据端点全部被 WAF 拦截（W1）+ 表单 JS 不可用（B4/W3），无法通过 UI 完成任何写操作。若修复 W1 与 B4，可按 `insert/update/delete` 端点补测。
- **登录后页面**：第二轮已全部实测（47/51 渲染成功，见 §4.2）；未覆盖的仅菜单跳转（W2 死链）与表格数据加载（W1/W3）。
- **apps/（Flutter/HarmonyOS 客户端）**：需真机/模拟器，本轮范围外（按任务约定聚焦 Web）。
- **service 业务 API 页面**：无 Web UI（8787 `/` 与 `/install.php` 均 404，纯 API），接口级测试由任务 #13 覆盖。
