## 2. Обнаруженные проблемы

### CRITICAL

#### C1. В развёртывании Docker отсутствует панель управления

**Проблема:** Dockerfile копирует только каталог `service/`, docker-compose проксирует только порт 8787. Панель управления (admin panel, порт 8788) вообще не докеризована.

```dockerfile
# docker/Dockerfile — 当前只处理 service
COPY service/ /app/
```

**Влияние:** пользователи развёртывания через Docker не могут использовать панель управления. Это не соответствует заявленному в README «однокомандному запуску Docker Compose».

**Рекомендация:** добавить Dockerfile для `admin/` или использовать многостадийную сборку для одновременного развёртывания обоих сервисов.

---

#### C2. Порт БД Docker раскрыт на хост-машину

**Проблема:** в docker-compose.yml порты MySQL (3306) и Redis (6379) напрямую маппятся на хост:

```yaml
mysql:
  ports:
    - "3306:3306"    # 暴露到公网
redis:
  ports:
    - "6379:6379"    # 暴露到公网
```

**Влияние:** если у сервера есть публичный IP, база данных будет доступна снаружи. Это частый источник инцидентов безопасности.

**Рекомендация:** убрать маппинг `ports` или как минимум привязать `127.0.0.1:3306:3306`. Внутренняя сеть Docker и так обеспечивает связность.

---

#### C3. Отсутствует файл LICENSE

**Проблема:** README объявляет «Lite — MIT License», но в корне проекта нет файла `LICENSE`.

**Влияние:** отсутствует обязательный юридический элемент open source. GitHub не распознает тип лицензии проекта.

**Рекомендация:** создать в корне `LICENSE` со стандартным текстом MIT License.

---

### HIGH

#### H1. Дублирующиеся SQL-файлы создают путаницу

**Проблема:** в проекте 3 файла SQL DDL:

| Файл | Строк | Таблиц | Статус |
|------|------|------|------|
| `install.sql` (корень) | 739 | 46 | **используется сейчас** |
| `admin/install.sql` | 152 | 7 (только wa_*) | старый, не удалён |
| `docs/database.sql` | 629 | 39 (только erik_*) | старый, не удалён |

**Влияние:** сопровождающие могут редактировать не тот файл, что приведёт к рассинхронизации.

**Рекомендация:** удалить `admin/install.sql` и `docs/database.sql` либо добавить в шапку файлов заметное уведомление об устаревании со ссылкой на `install.sql`.

---

#### H2. Мастер установки не создаёт базу данных аудита

**Проблема:** `install/index.php` при генерации `service/.env` включает конфигурацию БД аудита:
```ini
AUDIT_DB_DATABASE=cloud_platform_audit
```
но мастер никогда не создаёт эту базу. Если приложение после запуска попытается писать журнал аудита, возникнет ошибка `Unknown database`.

**Влияние:** функция журнала аудита недоступна, страдает соответствие требованиям.

**Рекомендация:** при выполнении установки на шаге 4 добавить `CREATE DATABASE IF NOT EXISTS cloud_platform_audit`.

---

#### H3. В Docker отсутствует сервис Elasticsearch

**Проблема:** в docker-compose.yml только три сервиса: app + mysql + redis. Технологический стек README явно перечисляет Elasticsearch 8.x как обязательный компонент.

**Влияние:** полнотекстовый поиск (товары, пользователи, заказы, тикеты) полностью недоступен в развёртывании Docker.

**Рекомендация:** добавить сервис Elasticsearch в docker-compose.yml.

---

#### H4. В Dockerfile отсутствуют расширения PHP

**Проблема:** Dockerfile устанавливает расширения PHP: `gd pdo_mysql zip bcmath redis`. Но проверка окружения требует 9 расширений, не хватает:
- `intl` (интернационализация PHP)
- `xml` (разбор XML)
- `fileinfo` (определение типов файлов)

**Влияние:** некоторые функции в среде Docker могут молчаливо отказывать.

**Рекомендация:** добавить недостающие расширения: `docker-php-ext-install intl xml fileinfo`

---

### MEDIUM

#### M1. admin/.env.example недостаточно подробен

**Проблема:** service/.env.example (146 строк) против admin/.env.example (64 строки): у второго заметно меньше комментариев и пунктов конфигурации.

**Рекомендация:** дополнить admin/.env.example пояснениями, как минимум пометить, какие поля должны совпадать со стороной service.

---

#### M2. HASHIDS_SALT захардкожен в .env.example

**Проблема:** в обоих файлах `.env.example`:
```ini
HASHIDS_SALT=cloud-platform-hashids
```
Если эксплуатация просто выполнит `cp .env.example .env`, не меняя значение, все экземпляры будут использовать одну соль.

**Рекомендация:** использовать плейсхолдер в `.env.example` и подчеркнуть в комментарии «обязательно сгенерировать уникальное случайное значение».

---

#### M3. Недействительная ссылка на странице успеха мастера установки

**Проблема:** ссылка на странице завершения установки — `href="#"`, нет реально кликабельного URL.

**Рекомендация:** как минимум показывать конкретный URL/порт с командой запуска.

---

#### M4. Docker не содержит мастер установки

**Проблема:** Dockerfile не копирует `install.php` или каталог `install/`. Пользователи Docker не могут воспользоваться мастером установки в один клик.

**Рекомендация:** явно задокументировать, что при развёртывании Docker нужна ручная настройка, либо интегрировать мастер в образ.

---

#### M5. Переменные окружения Docker Compose неполны

**Проблема:** в `environment` в docker-compose.yml отсутствуют многие необходимые конфигурации: ключи JWT, соль Hashids, ключи шифрования, SMTP, Stripe и др.

**Рекомендация:** дополнить полный список переменных окружения или сослаться на файл `.env`.

---

### LOW

В README развёртывание Docker описано несколькими строками: не сказано, как настраивать переменные окружения, инициализировать базу данных, открывать панель управления.

**Рекомендация:** добавить полную документацию развёртывания Docker.

---

#### L2. Отсутствует .editorconfig

**Проблема:** в проекте нет файла `.editorconfig`. Для проектов со многими контрибьюторами важны единые настройки отступов и концов строк.

**Рекомендация:** добавить стандартный `.editorconfig`: PHP — отступ 4 пробела, UTF-8, LF.

---

#### L3. Захардкоженные значения по умолчанию в коде можно централизовать

**Проблема:** в `install/index.php` множество захардкоженных значений по умолчанию (хост БД, порт, имя БД, имя администратора) — при изменении легко что-то упустить.

**Рекомендация:** вынести в определения констант в начале файла.

## 9. Заключение

Общее качество проекта хорошее; после прошлой ревизии все проблемы безопасности ключевого мастера установки исправлены. Код организован чётко, модульность высокая, документация полная. Основные проблемы сконцентрированы на **неполной конфигурации развёртывания Docker** — отсутствуют панель управления, поисковый сервис, расширения PHP, и есть риск раскрытия портов БД.

**Итог: B+** — функциональность полная, ядро безопасности на месте, конфигурацию экосистемы Docker нужно дополнить.
