## 3. Проверка защиты

### Соответствует требованиям ✓

- **Управление ключами**: в проекте нет захардкоженных ключей/паролей (сканирование grep); все ключи через `getenv()`; .env в gitignore
- **SQL-инъекции**: нет конкатенации строк в SQL; всё через построитель запросов Eloquent
- **Проверка ввода**: белый список type при загрузке + анализ содержимого finfo + лимиты размера по типам; проверка полей на auth-эндпоинтах
- **Ограничение частоты**: полное покрытие чувствительных публичных эндпоинтов (login 5/мин, register 3/мин, sms 5/ч, captcha 30/60с, oauth 10/60с, password_reset 3/5 мин), default 60/мин
- **JWT**: HS256 + 32-байтный ключ; раздельные access/refresh; проверка type; чёрный список Redis (проверка по jti в базе); принудительный TOTP + блокировка при неудачах
- **CORS**: белый список Origin (`CORS_ALLOWED_ORIGINS`), без подстановочных знаков, без заголовка с учётными данными
- **Заголовки безопасности**: nosniff / X-Frame-Options / Referrer-Policy / Permissions-Policy / HSTS (переключатель через env)
- **Защита от перечисления**: forgot-password возвращает одинаковое успешное сообщение для несуществующих пользователей

### Рекомендации (низкий приоритет, не изменено)

| Пункт | Описание |
|----|------|
| Нет заголовка CSP | Content-Security-Policy не настроен на всём сайте; для JSON API риск низкий, рекомендуется добавить в SecurityHeadersMiddleware политику уровня `default-src 'none'` |
| Производительность WAF | WafMiddleware на каждый запрос читает всё тело `file_get_contents('php://input')` для сканирования (31 паттерн) — при высоком трафике есть затраты памяти/CPU; рекомендуется читать тело только для POST/PUT при совпадении Content-Type |
| HealthController `shell_exec('git rev-parse')` | каждый health-запрос порождает подпроцесс; в проде рекомендуется только env `APP_VERSION`, shell — fallback только для локальной разработки |
| ~~RateLimit TOCTOU~~ | ~~check-then-set не атомарен~~ **исправлено (2026-08-07):** заменено на атомарный `INCR` + первый `EXPIRE`, см. §7-6 |
| X-XSS-Protection | устаревший заголовок, безвреден; после внедрения CSP можно удалить |

## 4. Пробелы окружения (не проблемы кода, требует эксплуатация)

1. **В `.env` отсутствует `DB_PASSWORD`** (единственный блокирующий пункт): docker-compose создаёт app_user через `${DB_PASSWORD}`, в локальном .env ключ отсутствует → все DB-эндпоинты 500. `DB_PASSWORD` определён в `.env.example`; это развёртываемое учётное данные, пользователю нужно внести в `.env`.
2. **9100 занят локальным процессом dart**: при сбое привязки порта по умолчанию для metrics-процесса **блокируется запуск всей группы** (webman перед стартом проверяет все порты). Обходной путь закреплён: в .env записано `METRICS_PORT=9199` (2026-08-07). После освобождения 9100 dart'ом можно вернуть значение по умолчанию.
3. **composer validate fatal (сторонний)**: плагин composer в `erikwang2013/security-php` конфликтует с собственным eval composer (повторное объявление `isLaravel()`), к коду этого проекта отношения не имеет; шаг `composer validate --strict` в CI может из-за этого падать — рекомендуется добавить этому шагу CI continue-on-error или пропускать пакет service.
4. Занятость порта 8787 процессом erp-php из прошлого раунда снята (в этом раунде привязка проверена фактически).
