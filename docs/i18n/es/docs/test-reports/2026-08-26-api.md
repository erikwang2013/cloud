## Detalle de fallos
- `POST /api/auth/register(cifrado)` [auth-flow] status=-1 esperado=0 notas: code=-1 msg= dentro del sobre=Server internal error —— el cast Encryptable del modelo User carece de la clave de 16 bytes (aes-128-ecb); crear un usuario da 500 seguro (defecto de aplicación)
- `POST /api/auth/register(plano)` [auth-flow] status=500 esperado=200 notas: HTTP 500 body=Server internal error —— falta la clave Encryptable (defecto de aplicación)
- `POST /api/auth/login` [auth-flow] status=200 esperado=200 notas: code=401 msg=Invalid credentials —— el defecto de registro bloquea la cadena completa de login (el captcha es de un solo uso; reutilizarlo devuelve 422)

## Limitaciones
- El pago con Stripe es un servicio externo: `POST /api/orders/{id}/pay` solo verifica la ruta de manejo de errores (4xx/5xx); no es posible completar un pago real
- Endpoints `/admin/api/*` de service: el token de usuario normal debe dar 401/403 (AdminRole/RBAC); el token de administrador requiere una cuenta de administrador en service (no configurada en este entorno)
- El problema de la clave maestra de admin (B1) está corregido y re-probado: 8788 arranca con normalidad; las rutas captcha/dashboard/dict/export/login/CRUD funcionan todas (la copia se ha actualizado al archivo de rutas completo)
- Panel admin (copia 8788): todas las rutas operativas; la cadena de login (captcha+session+bcrypt) devuelve token con éxito; observación: los endpoints de listado user/order/product/config son accesibles sin cookie de sesión (HTTP 200, sin autenticación)
- Registro (ambas rutas de service dan 500): el cast Encryptable del modelo User carece de la clave de 16 bytes (aes-128-ecb, MissingEncryptionKeyException) → el registro no funciona y no se puede obtener token de usuario; los casos autenticados con token se omiten en conjunto; el login solo puede verificar las rutas de error 401/422, por el captcha de un solo uso y porque no hay ningún usuario con el que entrar
- Endpoints públicos: en esta ronda se han recuperado por completo products/{id}, help/{slug}, el webhook de Stripe y domain/* (los 500 por ModelNotFoundException y el problema de columnas ausentes en domain_tlds ya están corregidos)
- Límite de peticiones: por defecto 60 req/60s por IP; la prueba los evita con intervalos de 1s; algún 429 puntual es esperado
- WAF (plugin security-php): el detector dns_rebinding considera que Host=127.0.0.1 es una IP de red interna y lo bloquea por error (problema de configuración de la aplicación, ámbito W1-W3); este conjunto lo evita enviando un Host de dominio (forma real de despliegue) mediante la variable de entorno `TEST_HOST`; el bloqueo automático de IP (max_attempts=5) se almacena en archivo y se libera automáticamente a los 15 minutos de dispararse el tráfico de prueba
