## Problemas de código de negocio encontrados (sin modificar, registrados por restricción)

1. **Doble codificación de Alert.context**: `AlertEngine::trigger()` pasa a `Alert::create` el string `json_encode($context)`, y el modelo Alert tiene cast `array` en `context`; setAttribute vuelve a hacer json_encode → se persiste doblemente codificado, y al leer, `$alert->context` es un JSON **string**, no un array (`app/Monitor/Service/AlertEngine.php` + `app/Monitor/Model/Alert.php:20`). Los tests lo verifican según el comportamiento real y lo comentan. Sugerencia: AlertEngine debe pasar un array.
2. **Doble punto en el dominio de Domain register**: `DomainService::register()` concatena `$domainName . '.' . $tld`, pero la tabla de configuración de tld guarda el punto (`.com`) → genera `example..com` (`app/Domain/Service/DomainService.php:40`). Los tests lo verifican según el comportamiento real y lo comentan. Sugerencia: quitar el punto del tld antes de concatenar.

## Huecos restantes y motivos

| Hueco | Motivo |
|------|------|
| collectAllMetrics / checkDowntime / checkSslCertificates de ResourceMonitor | Dependen de Redis + ProviderFactory (llamadas reales a proveedores) y del sondeo de sockets TLS; requieren capa de mock o entorno de integración; coste alto para test unitario |
| Ruta principal ES de ProductService (searchKeywordIds con acierto en ES) | Requiere contenedor ES real (el ProductSearchTest existente ya usa markTestSkipped con las instrucciones); en el entorno de test unitario no hay scout engine, `Product::search` devuelve array vacío sin excepción y la rama de degradación SQL no se puede disparar en unitario |
| Render de plantillas de NotificationDispatcher (getLocalizedTitle/body) | El NotificationDispatcherTest existente ya cubre la ruta base; el render multilingüe de plantillas es capa de I18n |
| Ejecución de resolvers Graphql (la consulta products devuelve resultados reales) | Los resolvers dependen de los modelos Product/Resource/Order; la estructura del Schema ya está cubierta, la ruta de ejecución se recomienda probarla con tests de integración de API |
