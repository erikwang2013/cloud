## Problemas y análisis de fallos

### Problema 1 (falso positivo, no defecto): `Cannot read properties of undefined (reading 'Account')` al conectar directo a una página
- Síntoma: al escanear conectando directo a `/app/admin/xxx/index`, permission.js reporta `window.Admin.Account` undefined.
- Causa: `window.Admin` solo se inyecta en el index.html del marco principal; al conectar directo a una subpágina (sin marco principal) falta.
- Conclusión: en la ruta de uso real (clic en el sidebar para entrar al iframe) no aparece este error; no es un defecto.

### Problema 2 (defecto menor real): con avatar vacío, `<img src="null">` dispara un 404
- Síntoma: al cargar la lista de user se pide `/app/admin/user/null` → 404 en consola.
- Causa raíz: `admin/app/view/user/index.html:273` (igual en admin/index.html):
  `'<img src="'+encodeURI(d['avatar'])+'" ...'` — cuando el avatar es NULL, `encodeURI(null)` → cadena `"null"`, y el navegador lo resuelve como ruta relativa `/app/admin/user/null`.
- Impacto: solo las filas con avatar vacío muestran la imagen rota + 1 log de 404 en consola; sin impacto funcional.
- Sugerencia: `encodeURI(d['avatar'] ?? '')` o no renderizar el img si el valor está vacío.

### Problema 3 (diferencia de entorno, no defecto): 36 modelos apuntan a tablas `erik_*` que no existen en la base de datos
- Síntoma: las tablas reales de esta BD son `orders/products/...`, mientras que en `admin/app/model/` 36 modelos tienen `$table = 'erik_xxx'`, por lo que las tablas de esas listas no tienen datos (la página en sí renderiza 200 con normalidad).
- Nota: se verificó que la cadena de render de datos de esas páginas funciona mediante `CREATE TABLE erik_* LIKE tabla_base` temporal + inserción de filas de test e2e_; todo se borró tras la verificación (actualmente 0 tablas `erik_%`). Es un problema de entorno por inconsistencia de nombres; se sugiere unificarlo más adelante.
